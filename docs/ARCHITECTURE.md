# Application foundation

PAM is the downstream application and E00 orchestration owner in the approved design. Fourteen independently versioned upstream engines retain their own responsibilities and data ownership. The application must eventually compose their public contracts, not copy their internals or share their operational databases.

## This checkpoint

This repository currently contains a static dependency inventory, a metadata validator, original design references, a work registry and checks. It contains no task executor, planner, agent broker, worker, model adapter, storage service, network server, UI, legal-document generator or media renderer. The validation module checks development metadata only; its flags are not runtime security controls, authentication or permissions.

The first foundation is a narrowly authorized exception to dependency-first operational implementation. AM-07.01 through AM-07.08 retain their original IDs, prerequisites, requirements and acceptance criteria and remain planned. Their eight units are preserved alongside the separate PAM-000 foundation checkpoint. The full 122-task suite plan is a design reference, not a claim that this repository owns or implements every task.

## Future composition boundaries

E01 owns identity and policy. E02 owns intake. E03 owns correspondence. E04 owns discovery. E05 owns evidence and provenance. E06 owns processing. E07 owns verification. E08 owns factual investigation. E09 owns editorial development. E10 owns media production. E11 owns consent and rights decisions. E12 owns release packaging and corrections. E13 owns resources and commercial operations. E14 owns visual audit and workspaces.

Engine repositories are identified in config/foundation.json. All PAM integration states are deliberately not_connected and not_verified. This describes this application's connections only, not the implementation maturity of the independent engines. No source revision is pinned as qualified or imported as an executable dependency in this checkpoint.

Event schemas and proposed APIs in docs/approved-design remain design material. They are not implemented endpoints or accepted cross-engine contracts. Future integration requires exact accepted versions, current permissions, bounded execution, independent stores, uncertainty-aware recovery and source-bound acceptance evidence. A valid hash or historical receipt is not current authorization.

## Deployment independence

Country-specific data, deployment objectives, names, evidence and jurisdictional configuration belong outside reusable source. White labeling and localization remain downstream work. Future legal or creative outputs require their own verified integrations and acceptance; this scaffold provides neither a filing mechanism nor a production workflow.

## Stopping point

After the foundation is pushed and checked, stop PAM implementation. Work on independent upstream engines continues separately. No deployable application is released by this checkpoint.
